# Session Checklist

本线是伞形计划，自己不改代码。每轮开工 / 收尾针对的是「要推进哪条工作流」。

## 开工

1. 读 `plan.md` §1 决策、§4 波次，从 `todo.md` 选当前波次内未完成的项；复述目标与边界。
2. 确认归属：挂已有活跃线就进那条线的 `session_checklist.md`；新子计划就先建目录五件套，并按 `../AGENTS.md` 门禁问到 95% 把握。
3. 查冲突面（plan §5.2）：同一批次里不能有两个 worker 改同一个高冲突文件。
4. 性能相关项：先确认 M 组基准命令可用，记录 before 数字。
5. git status：只按显式路径 stage，不碰用户的未提交文件。

## 收尾

1. 对应子计划 / 活跃线的收尾步骤全部完成（构建、测试、冒烟、自动化）。
2. 性能相关项：贴 before / after 表；Windows 数字标注来源。
3. 工作流收口时写吸收笔记（plan §5.4）。
4. 更新本目录 `todo.md`、`feature_matrix.json`，在 `progress.md` 记一条；与代码同一提交或紧随的计划提交。
