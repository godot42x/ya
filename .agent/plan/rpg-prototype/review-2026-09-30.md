## 3. 硬编码与应归引擎的能力

`Player.lua`（198 行）+ `FollowCamera.lua` + `Actor.lua` 实质是一个 2D 玩法框架：

| 目前在脚本里 | 建议归属 |
| --- | --- |
| 精灵帧动画（图集网格 → `uvRect`、帧序列、帧率） | 引擎组件 `SpriteAnimation`（sheet 描述 + clip） |
| 脚底抬高 `footLift = (size.y − 1) / 2` | `Sprite2DComponent` pivot / anchor 字段 |
| 像素完美相机（整数缩放、`orthoHalfHeight` 取景、像素吸附；`TEXELS_PER_UNIT=16` 两处重复） | 相机 2D 字段：每单位像素数、像素吸附、整数缩放 |
| 平滑跟随 + 地图边界夹取 | 相机跟随组件 |
| 方向键 / 确认键表（Player、Dialogue 各一份） | InputMap（命名动作） |
| 逐字显示 | GUI 文本控件 reveal 能力 |
| 按格移动 + 补间 + 朝向 | 引擎自带 Lua 库（`Engine/Content/Lua/`），不进 C++ |

引擎侧新增代码的硬编码：
- `placePlayerAtSpawn` 写死实体名 `"Player"`。
- `world.spawnSprite` 写死探针贴图 `kSpriteTexture`（`GameplayLua.cpp`）。
- `world.viewAspect`（手写 sol2）与 `world.viewSize`（中立层）重复。
- 地图实体必须叫 `TilemapGround`、对话条目必须叫 `"Dialogue"`：命名约定，没有发现机制。
- 新脚本函数一律经 `App::get()` 取单例。

## 5. 2D 实现方式

用 3D 节点承载 2D 不是问题（Unity 同构，R4 测得 Transform + 提取约 0.1ms）；游戏 2D 与 UI 2D 两类节点也正常
（Godot 的 `Node2D` / `Control`）。差距在渲染层：

- Godot 两类节点共用一个 canvas 渲染器（统一合批，树序 + z_index + y_sort，不依赖深度）。
  这里是两套：世界精灵走延迟管线里的 `Sprite2DStage`，逐精灵一次 draw，靠深度排序；
  UI 走 `ScreenDrawList`，自带合批。各自一张 16 槽纹理表、各自的 quad 格式。
- 纯 2D 场景也跑整条延迟链（GBuffer、光照、天空盒、Bloom、后处理）。
- 深度排序只适合像素风：alpha 裁剪 + 写深度，换抗锯齿边缘的美术就出问题，前后遮挡只能靠 z 叠 ε。

建议：节点树不变（不做 Node2D），渲染分两步：
1. 共享 2D quad 合批核心（实例格式、纹理表、按 pipeline + 纹理分批），世界精灵（相机矩阵 + y-sort）
   与 `ScreenDrawList`（像素空间 + 裁剪）作为两个前端。
2. 纯 2D View 的 2D 渲染家族：只有 sprite + compose，画家算法（layer → y → order），不写深度；§1 的 z 约定删除。

## 6. 性能（R4 TownLarge，5134 候选，Apple M5，profile）

- **正确性 bug：双面 quad**。共享 quad 有正反两套三角形（12 个索引），`Sprite2DStage.cpp` 设 `cullMode None`，
  每个精灵光栅化两遍；半透明精灵被混合两次，颜色错。改单面或给精灵独立 4 顶点网格。
- **逐候选提交主导**：约 1.2µs/候选，每 draw 四次命令调用（push constant、绑 VB、绑 IB、drawIndexed），
  合计约 6.3ms，占 10.6ms 帧的 60%，线性增长 → 精灵实例化。
- **纹理表每帧重建**，`slotFor` 线性查找（每帧约 8 万次比较）→ 直接映射。
- **tilemap 每帧重新展开**（现 0.1ms）→ 每图层 / 区块一份 GPU 实例缓冲，只在编辑时重建；视口裁剪等地图变大再按区块做。
- **`Render/Frame` self 2.9–5ms 未归因**，可能比逐候选提交更大（比如等帧栅栏）→ 先补 pass 级计时再定优化上限。
  读数注意帧限速把小场景夹在 8.33ms。

建议优先级：① 修双面 quad + 补 `Render/Frame` 归因 → ② 精灵实例化 + tilemap 静态实例缓冲 →
③ 2D 模块 + 2D 渲染家族 + y-sort → ④ 资源句柄化（已立计划）→ ⑤ B2 收口 + §3 能力进引擎 + 去硬编码。
